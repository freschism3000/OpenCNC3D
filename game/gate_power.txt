# THE POWER INDICATOR (v0.5.9): the colour is a WATT test, not a pixel one.
#
# TWO DEFECTS, one per sidebar.
#
#   THE DOS BAR compared bar PIXELS where 1995 compares watts:
#       power.cpp:475-482   if (PlayerPtr->Drain > PlayerPtr->Power)     YELLOW
#                           if (PlayerPtr->Drain > PlayerPtr->Power * 2) RED
#   Our db_draw_power tested `dh > ph` and `dh > ph * 2` on the heights. Those heights
#   come from Power_Height (power.cpp:425), which adds a SIXTH OF WHAT IS LEFT per 100
#   units, so it saturates: 200 watts against 500 is 33 pixels against 63. The watt rule
#   calls that RED and the pixel rule calls it YELLOW. Red was very nearly unreachable.
#
#   THE 640x480 ART HUD had no warning at all: one green channel however bad the drain
#   was, so the two sidebars in the same build disagreed about whether the base was in
#   trouble. It now takes the same watt rule.
#
# WHAT IS MEASURED is the colour each sidebar DREW, read back out of its own pixels by
# `powerdrawn`, one shot per sidebar (`hud 0`, then `hud 1`). powerdump's colour_by_watts
# and colour_by_pixels are what each rule WOULD choose; they are printed to prove the
# state below really separates the two rules, not as the thing under test.
#
# PART 1, SCB35EA as it starts: the Brotherhood is genuinely overdrawn, 430 produced
# against 475 drained, and both sidebars must draw YELLOW. Both rules agree there, so this
# part proves the real watts reach the drawn colour, not which rule decides it.
#
# PART 2 is the part that tells the rules apart. No shipped scenario starts with drain
# above TWICE production, so `powerforce 200 500` replaces the brain's two numbers where
# the sidebar receives them: RED by watts, YELLOW by bar pixels. Both sidebars must draw
# RED. The reading is forced, not played to, and that is said here plainly.
